# Pixel Language Village

## 웹 기반 카드 언어학습 앱 개발 계획서 / PRD

-   문서 버전: v0.1
-   개발 방식: 웹 기반, 단계적 MVP 개발
-   핵심 스택: Next.js + TypeScript + Supabase + GitHub + Vercel
-   기본 언어: 한국어
-   선택 외국어: 영어, 일본어, 스페인어
-   디자인 방향: 픽셀아트 기반 카드 및 성장형 마을

------------------------------------------------------------------------

# 1. 프로젝트 개요

## 1.1 한 줄 정의

글자를 카드로 익히고, 익힌 카드를 조합해 문장을 만들며, 학습한 단어와
문장이 픽셀 마을의 성장과 주민들의 생활로 나타나는 웹 기반 언어학습 앱.

## 1.2 핵심 목표

1.  유아의 한글 첫 읽기부터 초등학생의 어휘 확장까지 하나의 서비스에서
    이어지도록 한다.
2.  콘텐츠 DB는 중학교 수준 어휘까지 확장할 수 있도록 설계한다.
3.  단어를 단순 암기하지 않고 그림, 뜻, 예문, 문장 조합을 통해
    반복적으로 사용하게 한다.
4.  한국어 학습을 기본으로 하고 영어, 일본어, 스페인어를 선택하여 같은
    의미를 다른 언어로 학습할 수 있게 한다.
5.  학습량을 숫자로만 보여주지 않고 픽셀 마을의 성장으로 시각화한다.
6.  아이가 익힌 단어와 예문이 마을 주민의 행동과 대화로 다시 나타나
    자연스럽게 복습하게 한다.

------------------------------------------------------------------------

# 2. 개발 원칙

## 2.1 핵심 원칙

-   기능을 한 번에 모두 만들지 않는다.
-   전체 구조는 확장 가능하게 설계하되 MVP는 작게 시작한다.
-   첫 목표는 "카드 10장으로 전체 학습 순환이 실제 작동하는 것"이다.
-   콘텐츠와 프로그램 로직을 분리한다.
-   특정 언어에 종속된 DB 구조를 만들지 않는다.
-   픽셀아트는 학습을 방해하는 장식이 아니라 의미와 학습 결과를
    시각화하는 장치로 사용한다.
-   아이의 실제 학년을 난이도 라벨로 직접 노출하지 않는다.

## 2.2 첫 번째 완성 기준

다음 흐름이 처음부터 끝까지 실제 웹에서 작동해야 한다.

`보호자 로그인 → 아이 프로필 선택 → 학습 언어 선택 → 단어 카드 학습 → 학습 상태 저장 → 기록 증가 → 마을 성장 반영`

# 3. 대상 사용자

## 3.1 주요 사용자

-   한글을 처음 읽기 시작하는 유아
-   읽기와 어휘 학습이 필요한 초등학생
-   초등 고학년의 학습·교과 어휘 학습자

## 3.2 콘텐츠 확장 범위

-   유아 기초어휘
-   초등 기초어휘
-   초등 확장어휘
-   초등 교과어휘
-   중학교 기초·확장·교과 어휘

앱 화면에서는 `5세`, `초등 3학년` 등의 라벨보다 `Level 1`, `Level 2`
방식으로 보여준다.

내부 데이터에는 학년 수준, 교육과정 수준, 어휘 난이도 등의 메타데이터를
별도로 보관할 수 있다.

# 4. 서비스 핵심 구조

서비스는 네 개의 핵심 영역으로 구성한다.

## 4.1 단어 모드

단어 카드를 읽고 뒤집어 의미를 확인한다.

## 4.2 문장 모드

익힌 단어 카드를 움직이고 조합하여 문장을 만든다.

## 4.3 마을

학습량에 따라 성장하며 익힌 단어와 예문이 주민 행동 및 대화로 나타난다.

## 4.4 기록

익힌 단어, 익힌 문장, 학습시간, 언어별 진행도를 누적하여 보여준다.

# 6. 언어 시스템

## 6.1 지원 구조

기본 언어:

-   한국어

선택 외국어:

-   영어
-   일본어
-   스페인어

사용자는 외국어를 선택하거나 변경할 수 있다.

## 6.2 DB 설계 원칙

다음처럼 언어별 컬럼을 만들지 않는다.

``` text
korean_word
english_word
japanese_word
spanish_word
```

대신 언어 코드를 사용한다.

예:

``` text
concept_id: apple
language_code: ko
text: 사과

concept_id: apple
language_code: en
text: apple

concept_id: apple
language_code: ja
text: りんご

concept_id: apple
language_code: es
text: manzana
```

이를 통해 향후 다른 언어를 추가해도 DB 구조를 변경하지 않도록 한다.

# 7. 카드 시스템

## 7.1 카드의 정의

카드는 특정 언어의 단어가 아니라 먼저 하나의 `의미(concept)`를 가진다.

예:

``` text
Concept: APPLE
Part of Speech: noun
Visual: apple_pixel.png

ko → 사과
en → apple
ja → りんご
es → manzana
```

## 7.2 카드 기본 데이터

각 의미 카드에는 다음 정보가 필요하다.

-   concept_id
-   의미 분류
-   품사
-   어휘 난이도
-   학습 영역
-   그림 사용 적합 여부
-   픽셀아트 이미지
-   언어별 표기
-   언어별 발음 정보
-   언어별 정의
-   언어별 예문
-   문장 조합용 문법 정보

## 7.3 품사

초기부터 다음을 지원할 수 있는 구조로 만든다.

-   명사
-   대명사
-   동사
-   형용사
-   부사
-   수사
-   관형어/한정 표현
-   조사·전치사 등 문법 요소
-   접속 표현
-   기타 학습용 언어 블록

------------------------------------------------------------------------

# 8. 난이도별 카드 표현

모든 어휘를 억지로 그림으로 표현하지 않는다.

## Level 1: 그림 중심

예:

``` text
앞면: 사과
뒤면: 픽셀 사과 + 사과 + 발음
```

## Level 2: 그림 + 짧은 예문

``` text
달리다
[달리는 픽셀 캐릭터]
친구가 운동장을 달려요.
```

## Level 3: 상황 + 예문

``` text
서운하다
친구가 나만 빼고 놀아서 서운했어요.
```

## Level 4 이상: 뜻 + 예문 중심

``` text
관점

어떤 대상이나 일을 바라보는 생각의 위치나 방식.

같은 사건도 어떤 관점에서 보느냐에 따라
다르게 해석할 수 있어요.
```

픽셀아트는 이 단계에서 개념 설명의 보조 요소로 사용한다.

------------------------------------------------------------------------

# 9. 어휘 난이도 체계

어휘의 어려움과 학습 활동의 어려움을 분리한다.

## 9.1 어휘 레벨

내부 기준 예시:

-   기초 생활어
-   일상어
-   초등 기초
-   초등 확장
-   초등 교과
-   중학교 기초
-   중학교 확장·교과

실제 어휘 DB 구축 시 교육과정, 교과서, 공신력 있는 어휘 자료 등을 근거로
별도 검증한다.

## 9.2 카드 숙련도

각 단어는 아이별로 별도의 숙련도를 가진다.

``` text
0 = 처음 만남
1 = 읽음
2 = 의미 이해
3 = 문장 활용
4 = 익힘
```

단순히 카드를 한 번 뒤집은 것을 `익힘`으로 계산하지 않는다.

# 10. 단어 모드

## 10.1 기본 동작

1.  카드 앞면 표시
2.  아이가 단어 읽기
3.  카드 터치
4.  3D 또는 2D flip 애니메이션
5.  뒷면 표시
6.  그림/뜻/예문 확인
7.  발음 듣기
8.  자기 평가 또는 간단한 확인 활동
9.  학습 결과 저장
10. 다음 카드 이동

## 10.2 복습

학습 기록을 기반으로 다음 세션에 카드를 재노출할 수 있도록 한다.

초기 MVP에서는 복잡한 알고리즘 대신 다음 정도로 시작한다.

-   어려움 → 가까운 시점에 다시 노출
-   보통 → 일정 카드 이후 다시 노출
-   알고 있음 → 이후 세션에서 복습

추후 간격 반복 학습 알고리즘으로 확장 가능하게 한다.

# 11. 문장 모드

## 11.1 핵심 개념

단어 모드에서 익힌 카드가 문장 모드의 재료가 된다.

예:

``` text
고양이 | 살금살금 | 걷다
```

한국어 문장:

``` text
고양이가 | 살금살금 | 걸어요.
```

## 11.2 1차 문장 모드

MVP에서는 자유 문장 생성보다 `미리 검증된 문장 패턴`을 사용한다.

예:

``` text
[주어] + [목적어] + [동사]
[주어] + [부사] + [동사]
[주어] + [형용 표현]
```

## 11.3 확장 문장 모드

이후 단계에서:

-   빈칸 문장
-   카드 순서 맞추기
-   카드 자유 배열
-   자유 문장 만들기
-   같은 의미를 다른 언어로 배열하기

를 추가한다.

# 12. 언어별 문법 블록

같은 의미를 언어별 문법에 맞게 재배열한다.

예시 의미:

``` text
나 / 사과 / 먹다
```

한국어:

``` text
나는 | 사과를 | 먹어요.
```

영어:

``` text
I | eat | an apple.
```

일본어:

``` text
わたしは | りんごを | 食べます。
```

스페인어:

``` text
Yo | como | una manzana.
```

## 12.1 시각적 원칙

언어를 변경할 때 단순 번역 결과로 교체하지 않는다.

-   카드 위치가 이동한다.
-   필요한 문법 블록이 붙는다.
-   동사 형태가 변한다.
-   관사나 조사 등이 나타난다.

아이에게 문법 용어를 먼저 설명하기보다 카드 변화로 규칙을 경험하게 한다.

## 12.2 구현 원칙

초기에는 언어별 문법 엔진을 직접 만들지 않는다.

`검증된 문장 패턴 + 문법 메타데이터` 방식으로 구현한다.

향후 문법 엔진 또는 AI 기반 자유 문장 검증은 별도 단계에서 검토한다.

# 14. 픽셀 마을 시스템

## 14.1 목적

마을은 단순한 게임 보상이 아니다.

두 가지 역할을 한다.

1.  학습량을 시각화한다.
2.  익힌 단어와 예문을 상황 속에서 다시 만나는 복습 공간이 된다.

## 14.2 테마 랜덤 배정

프로필 생성 시 마을 테마를 랜덤 배정한다.

테마 예:

-   바닷속 왕국
-   중세 왕국
-   한국 옛마을
-   현대 도시
-   외계 행성
-   달빛 마을
-   구름 위 마을
-   세계수 마을
-   버섯 숲
-   눈과 얼음 마을
-   사막 오아시스
-   무인도
-   공룡시대
-   해적섬
-   마법사 마을
-   요정 숲
-   고양이 마을
-   동물 숲
-   과자 왕국
-   로봇 도시
-   우주정거장
-   수정 동굴
-   꽃의 정원
-   증기기관 도시
-   산꼭대기 마을
-   화산섬
-   용의 계곡
-   소행성 마을
-   책 속 마을
-   놀이공원

테마는 학습 난이도에 영향을 주지 않는다.

## 14.3 성장 규칙

예시:

``` text
단어 학습 → 건물 / 식물 / 주민 증가
문장 학습 → 주민 행동 / 대화 / 이벤트 증가
장기 성취 → 새로운 구역 개방
```

정확한 숫자 기준은 사용자 테스트 후 조정할 수 있도록 DB/설정값으로
관리한다. 코드에 고정하지 않는다.

# 15. 마을 속 예문

이 기능은 핵심 학습 기능으로 본다.

예:

아이에게 `관찰하다` 카드가 익숙해짐.

마을에 새싹을 보고 있는 주민 등장.

주민 터치:

``` text
"나는 새싹이 자라는 모습을 관찰하고 있어."
```

`서두르다`를 익혔다면:

``` text
"버스를 놓칠까 봐 정류장으로 서둘러 가고 있어."
```

## 구현 원칙

-   최근 학습 단어 우선
-   복습이 필요한 단어 우선
-   한 화면에 너무 많은 예문을 노출하지 않음
-   예문 속 핵심 단어 강조
-   단어 터치 시 원래 카드로 이동 가능

# 17. GitHub 역할

GitHub는 `코드와 개발 이력`을 관리한다.

## 기본 원칙

-   `main`: 실제 서비스 배포 기준
-   기능 개발은 별도 브랜치
-   완성된 기능만 main에 병합
-   중요한 단계마다 commit

브랜치 예:

``` text
main
feature/auth
feature/word-card
feature/progress
feature/village
feature/sentence-mode
feature/language-selector
```

## 권장 개발 흐름

``` text
새 기능 개발
↓
```

# 18. Supabase 역할

Supabase는 `앱의 기억`을 담당한다.

## Supabase Database

저장 대상:

-   사용자
-   아이 프로필
-   언어 설정
-   의미 카드
-   언어별 단어
-   예문
-   문장 패턴
-   카드별 학습 상태
-   학습 세션
-   만든 문장
-   마을 상태
-   마을 이벤트

## Supabase Auth

보호자 계정 로그인에 사용한다.

아이마다 별도 이메일 계정을 만들지 않고 보호자 계정 아래에 여러
`child_profile`을 둘 수 있도록 설계한다.

## Supabase Storage

저장 대상:

``` text
/card-art/
    nouns/
    verbs/
    scenes/

/village/
    ocean/
    medieval/
    korean/
    space/
```

픽셀아트 이미지는 DB에 직접 저장하지 않고 Storage의 경로를 DB에서
참조한다.

## Security

-   RLS 적용
-   보호자는 자신의 child_profile 데이터만 읽고 수정 가능
-   공개 학습 콘텐츠와 개인 학습기록을 분리

## 역할

-   Next.js 앱 호스팅
-   GitHub 연동
-   Preview Deployment
-   Production Deployment
-   환경변수 관리

## 배포 흐름

``` text
로컬/AI 코딩
↓
GitHub
↓
Vercel Preview
↓

↓
main
↓
Vercel Production
```

Supabase URL 및 공개 가능한 클라이언트 키 등 필요한 환경변수는 Vercel

``` text
[현재 단계]

4. 모바일에서 정상 작동
5. 기존 로그인 기능을 깨뜨리지 않음

[하지 말 것]
DB schema 임의 변경 금지
다른 페이지 리팩터링 금지
```

# 42. 프로젝트 성공 기준

이 프로젝트의 성공 기준은 "기능이 많은 앱"이 아니다.

다음 세 가지가 실제로 연결되어 작동하는 것이 우선이다.

1.  **단어를 익힌다.**
2.  **익힌 말로 문장을 만든다.**
3.  **배운 말이 내가 키운 세계에 남는다.**

따라서 모든 신규 기능은 이 세 가지 중 하나를 강화하는 경우에만 우선
개발한다.
